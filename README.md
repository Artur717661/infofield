# InfoField — информационное поле университета

Аналитический дашборд для мониторинга упоминаний университета в Telegram и
ВКонтакте. Отдельный акцент — отслеживание «рекламы» образовательных программ,
в первую очередь **ИТ-специалитета**.

- `backend/` — FastAPI + PostgreSQL + Gemini NLP. Парсит каналы, размечает
  публикации и отдаёт их на `GET /telegram` и `GET /vk`.
- `frontend/` — React + TypeScript + Vite. Читает только эти два эндпоинта,
  всю аналитику считает на клиенте.

---

## Что нужно установить

| Что | Версия | Зачем |
|---|---|---|
| Python | 3.11+ | backend |
| PostgreSQL | 14+ | хранилище публикаций |
| Node.js | 20+ | frontend (проверено на 22) |
| Chromium для Playwright | — | парсер Telegram открывает страницу канала |

---

## Шаг 1. База данных

Создайте базу и пользователя:

```bash
# Linux / macOS
sudo -u postgres psql -c "CREATE DATABASE \"InfoField\";"
sudo -u postgres psql -c "ALTER USER postgres PASSWORD 'ваш_пароль';"
```

```powershell
# Windows (psql из установки PostgreSQL)
psql -U postgres -c "CREATE DATABASE \"InfoField\";"
```

Таблицы создавать вручную не нужно — `backend/databse.py` делает
`Base.metadata.create_all()` при первом импорте.

## Шаг 2. Настройки backend

Создайте файл `backend/.env`:

```env
GEMINI_API_KEY=ваш_ключ_google_gemini
DATABASE_URL=postgresql://postgres:ваш_пароль@localhost/InfoField
TG_CHANNEL_NAME=wearesiriusuniversity
VK_GROUP_NAME=siriusuniversity
```

`.env` в `.gitignore` — ключи в репозиторий не попадают.

## Шаг 3. Зависимости backend

```bash
cd infofield
python -m venv venv

source venv/bin/activate       # Linux / macOS
# venv\Scripts\activate        # Windows

pip install -r backend/requirements.txt
python -m playwright install chromium
```

## Шаг 4. Запуск backend

Из **корня проекта** (важно: импорты внутри backend абсолютные, вида
`from backend.config import ...`):

```bash
uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

Проверка:

```bash
curl http://127.0.0.1:8000/telegram
```

Первый запрос идёт долго: эндпоинт синхронно запускает парсер и отправляет
новые публикации в Gemini на разметку. Дальше он отдаёт данные из базы, а
парсер только дособирает новое и обновляет метрики.

## Шаг 5. Запуск frontend

В **новом терминале**:

```bash
cd infofield/frontend
npm install
npm run dev
```

Откройте **http://127.0.0.1:4174**

Vite проксирует `/telegram` и `/vk` на `http://localhost:8000`, поэтому
дополнительно ничего настраивать не нужно и CORS не требуется. Если backend
поднят на другом адресе, создайте `frontend/.env`:

```env
VITE_API_BASE_URL=http://адрес:порт
```

## Демо-данные за сентябрь 2025 — июль 2026

Чтобы показать дашборд, не дожидаясь реального парсинга и не тратя квоту
Gemini, есть генератор фикстур:

```bash
# backend должен быть остановлен, venv активирован, из корня проекта
python tools/seed_demo_data.py
```

Скрипт добавит ~1500 публикаций за 01.09.2025 — 31.07.2026 с сезонной
динамикой: спад в январскую сессию, рост к приёмной кампании, пики на Дне
открытых дверей и зачислении, несколько дней с негативом. Он **не меняет
backend** — только пишет строки в базу через штатные функции
`save_telegram_posts` / `save_vk_posts`.

Очистить демо-данные:

```bash
psql -U postgres -d InfoField -c "TRUNCATE telegram_posts, vk_posts;"
```

## Как пользоваться дашбордом

**Пять экранов** переключаются в шапке:

| Экран | Что показывает |
|---|---|
| Обзор | объём упоминаний с аномалиями (z-score), тональность, календарь активности, темы периода |
| Сущности | карта внимания по подразделениям, рейтинг персон по месяцам, связи «персона — событие» |
| Тренды | доля ИТ-специалитета в потоке по месяцам, путь публикации от анонса до охвата |
| Контент | лексикон абитуриентов/студентов против лексикона сотрудников, научные направления |
| ИТ-специалитет | доля в потоке, вовлечённость против средней, тональность, воронка, ключевые фразы |

**Фильтры сверху действуют на все экраны сразу:** период (пресеты + точные
даты), источник, аудитория, тональность, поиск, отдельный тумблер
«ИТ-специалитет». Счётчик справа показывает, сколько публикаций осталось
после фильтров.

**Любой элемент графика кликабелен.** Клик по точке графика, ячейке
календаря, сектору тональности, блоку подразделения, узлу графа, полосе
n-граммы или этапу воронки открывает панель справа с самими публикациями
этого среза: сводка (вовлечённость, просмотры, доля негатива), сортировка по
дате или вовлечённости и выгрузка в CSV. Закрыть — `Esc`, клик по фону или
крестик. Повторный клик по тому же элементу тоже закрывает панель.

Кнопка `↻` в шапке перезапрашивает backend, не перезагружая страницу.

## Если что-то не работает

**`ModuleNotFoundError: No module named 'backend'`** — uvicorn запущен не из
корня проекта. Перейдите в `infofield/` и повторите.

**`Executable doesn't exist at .../chrome-headless-shell`** — не установлен
браузер для Playwright: `python -m playwright install chromium`.

**На дашборде «Нет связи с backend»** — backend не отвечает на порту 8000.
Проверьте, что uvicorn запущен, и что `curl http://127.0.0.1:8000/telegram`
возвращает JSON.

**Дашборд пустой, но backend отвечает** — в базе нет публикаций. Либо
дождитесь парсинга, либо залейте демо-данные (см. выше).

**Ошибки Gemini `429 / квота исчерпана`** — бесплатный лимит API исчерпан.
Парсер сам ждёт и повторяет попытки; уже сохранённые публикации при этом
продолжают отдаваться.

**Windows блокирует `npm`** — используйте `npm.cmd install` и
`npm.cmd run dev`.

## Безопасность

Тексты публикаций приходят из внешних каналов, то есть это недоверенный
пользовательский ввод. Что сделано на стороне фронтенда:

- `Content-Security-Policy` и `Referrer-Policy` в `frontend/index.html`:
  скрипты только со своего origin, без `unsafe-eval`, `object-src 'none'`.
- Текст постов рендерится только как текстовый узел React.
  `dangerouslySetInnerHTML` не используется нигде — вложенная в пост разметка
  не исполнится.
- Запросы к API идут с `credentials: "omit"` и `referrerPolicy: "no-referrer"`.
- Экспорт в CSV экранирует ячейки, начинающиеся с `=`, `+`, `-`, `@`, чтобы
  выгрузка не превратилась в формулу при открытии в Excel.
- `.env` с ключами исключён из git.

**При выкладывании в интернет** добавьте на уровне reverse proxy заголовки,
которые нельзя задать через `<meta>`: `X-Frame-Options: DENY`,
`X-Content-Type-Options: nosniff`, `Strict-Transport-Security`, а на backend —
CORS-allowlist строго с origin фронтенда (не `*`) и рейт-лимит на `/telegram`
и `/vk`, поскольку каждый запрос к ним запускает парсинг.

В `.claude/skills/` лежат три чек-листа по веб-безопасности из
[Anthropic-Cybersecurity-Skills](https://github.com/mukul975/Anthropic-Cybersecurity-Skills)
(аудит security-заголовков, проверка на XSS, проверка CORS) — по ним удобно
проверять развёрнутый стенд.

## Ограничения текущей версии

Честно о том, чего в дашборде нет и почему:

- **Max не подключён** — в backend нет коннектора к его API, только Telegram и
  ВКонтакте. Фильтр по источникам строится из того, что реально пришло.
- **Нет heatmap активности 24×7** — колонка `post_date` в базе хранит только
  дату без времени, час публикации взять негде. Вместо выдуманных часов —
  календарь активности по дням.
- **«Просмотры» — это измеренные `views` публикаций**, а не суммарная
  аудитория каналов: размер аудитории API не отдаёт.
- **N-граммы считаются по тексту постов** и осмысленны только пока backend
  возвращает поле `text`.
