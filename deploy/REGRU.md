# Публикация InfoField на рег.ру

Инструкция под панель управления reg.ru. Общая инструкция по серверу —
в [`DEPLOY.md`](DEPLOY.md), здесь только то, что делается на сайте рег.ру.

> Названия кнопок в панели рег.ру периодически меняются. Если формулировка
> отличается — ищите раздел по смыслу, логика шагов остаётся той же.

---

## Шаг 0. Сначала выясните, что именно вы купили

Это главный шаг. На рег.ру под словом «хостинг» продаются два разных продукта,
и на одном из них проект **не запустится**.

Зайдите в **[личный кабинет](https://www.reg.ru/user/account/)** → раздел
**«Мои услуги»** (или «Услуги» / «Хостинг и серверы») и посмотрите название
вашей услуги:

| Что написано | Что это | Проект заработает? |
|---|---|---|
| «Виртуальный хостинг», тариф вида Host-0 / Host-1 / Host-2 | shared-хостинг, только PHP | **Нет** |
| «VPS», «Облачный сервер», тариф вида Cloud-1 / VPS-1 | свой сервер с root | **Да** |
| «Выделенный сервер», «Dedicated» | физический сервер | Да |

### Почему на виртуальном хостинге не заработает

Это не особенность нашего кода — это ограничения самого тарифа, и рег.ру
пишет о них в своей документации:

- **нет прав root** — нельзя поставить PostgreSQL, nginx, Chromium;
- **долгоживущие процессы принудительно останавливаются** — а backend и шлюз
  должны работать постоянно, это не PHP-скрипты, которые запускаются на один
  запрос;
- **нет PostgreSQL** — на виртуальном хостинге только MySQL;
- **нет Chromium** — парсер Telegram открывает страницу канала в браузере.

Рег.ру в своей же статье про Python-хостинг прямо пишет, что виртуальный
хостинг для Python-проектов не подходит и рекомендует VPS или выделенный
сервер.

### Что делать, если у вас виртуальный хостинг

1. Напишите в поддержку рег.ру (чат в личном кабинете или
   support@reg.ru): опишите, что вам нужен VPS вместо виртуального хостинга,
   и спросите про перенос средств или возврат за неиспользованный период.
   Условия зависят от того, сколько прошло с оплаты — пусть скажут они, а не
   я угадаю.
2. Закажите VPS (шаг 1 ниже).
3. **Домен info-field.ru при этом никуда не денется** — он у вас отдельная
   услуга, для него достаточно поменять IP в A-записи.

## Шаг 1. Заказ VPS

Личный кабинет → **«Хостинг и серверы»** → **«Серверы VPS»** → «Заказать».

### Сколько ресурсов реально нужно

Замерено на работающем стеке, а не взято из головы:

| Компонент | Память | Когда |
|---|---:|---|
| Ubuntu 24.04 | ~180 МБ | постоянно |
| PostgreSQL | ~120 МБ | постоянно |
| backend (uvicorn) | ~150 МБ | постоянно |
| gateway (uvicorn) | ~90 МБ | постоянно |
| nginx | ~20 МБ | постоянно |
| **Итого в покое** | **~560 МБ** | сайт открыт и работает |
| Chromium при парсинге | +300 МБ | 4 раза в сутки по таймеру |
| **Пик** | **~860 МБ** | во время сбора данных |
| `npm run build` | +243 МБ | только при развёртывании |

Диск: Ubuntu ~4 ГБ + Chromium ~0,9 ГБ + Python-пакеты ~250 МБ +
`node_modules` ~86 МБ + база ~9 МБ на 1500 публикаций ≈ **6 ГБ**.

| RAM | Вердикт |
|---|---|
| 1 ГБ | тесно: в покое свободно ~460 МБ, при парсинге ~160 МБ. Работает, но нужны настройки из раздела ниже |
| 2 ГБ | комфортно, запас ~1,2 ГБ на пике |
| 4 ГБ | с большим запасом |

### Параметры при заказе

| Параметр | Значение | Почему |
|---|---|---|
| ОС | **Ubuntu 24.04** (или 22.04) | под неё написан скрипт настройки |
| Панель управления | **без панели** | ISPmanager поставит свой nginx и займёт порты 80/443; лицензия платная и здесь не нужна |
| CPU | 1 ядра хватит, 2 лучше | парсинг на одном ядре просто медленнее |
| RAM | **2 ГБ**, минимум 1 ГБ с настройками ниже | Chromium |
| Диск | 15 ГБ хватает, 20+ спокойнее | Chromium весит ~0,9 ГБ |

## Если у вас тариф с 1 ГБ RAM

Проект запустится, но по умолчанию при парсинге памяти почти не остаётся, и
ядро может убить случайный процесс — например PostgreSQL, и тогда упадёт весь
сайт. Четыре шага убирают риск.

### 1. Swap — сделайте это первым делом

```bash
fallocate -l 2G /swapfile
chmod 600 /swapfile
mkswap /swapfile && swapon /swapfile
echo '/swapfile none swap sw 0 0' >> /etc/fstab
# Свопить только при реальной нехватке, а не заранее
sysctl -w vm.swappiness=10
echo 'vm.swappiness=10' >> /etc/sysctl.conf
free -h
```

### 2. Ужать PostgreSQL

```bash
cp /opt/infofield/deploy/systemd/lowmem/postgresql-lowmem.conf \
   /etc/postgresql/16/main/conf.d/lowmem.conf
systemctl restart postgresql
```

Освобождает ~60 МБ. База у нас крошечная, уменьшенные буферы её не замедлят.

### 3. Изолировать парсер, чтобы он не утянул сайт

```bash
mkdir -p /etc/systemd/system/infofield-backend.service.d
cp /opt/infofield/deploy/systemd/lowmem/infofield-backend-lowmem.conf \
   /etc/systemd/system/infofield-backend.service.d/lowmem.conf
systemctl daemon-reload && systemctl restart infofield-backend
```

Теперь при нехватке памяти OOM случается внутри backend'а: умирает только
парсер, сайт продолжает работать на кэше шлюза, systemd поднимает backend через
5 секунд.

### 4. Собирать фронтенд не на сервере

`npm run build` берёт ещё 243 МБ — вместе с работающими сервисами это почти
весь гигабайт. Проще собрать у себя на компьютере и загрузить готовую папку:

```bash
# на своём компьютере, в папке проекта
cd frontend && npm ci && npm run build

# загрузить dist на сервер (WinSCP/FileZilla по SFTP или командой)
scp -r frontend/dist root@ВАШ_IP:/opt/infofield/frontend/
```

Тогда Node.js на сервере вообще не нужен — пропустите шаг с `nodesource`
в разделе установки.

> Если всё же собираете на сервере, остановите сервисы на время сборки:
> `systemctl stop infofield-backend infofield-gateway`, собрать, потом
> `systemctl start infofield-backend infofield-gateway`.

### Проверить, что памяти хватает

```bash
free -h                        # сколько занято и сколько ушло в swap
dmesg | grep -i "out of memory"   # были ли убийства процессов
systemctl status infofield-backend --no-pager   # не перезапускался ли по кругу
```

> **Для защиты проекта** парсер можно вообще выключить:
> `systemctl disable --now infofield-refresh.timer`. Демо-данные за сентябрь
> 2025 — июль 2026 уже в базе, дашборд работает от них, Chromium не запускается,
> и 1 ГБ хватает с большим запасом.

> Если панель ISPmanager уже включена в ваш тариф — её можно не использовать.
> Наш `setup-server.sh` ставит свой nginx; если ISPmanager уже занял порты 80
> и 443, отключите его вебсервер или переустановите ОС «без панели»
> (шаг 2).

## Шаг 2. Если ОС не Ubuntu — переустановите

Личный кабинет → ваша услуга VPS → вкладка **«Операции»** (или «Управление») →
**«Переустановить ОС»** → выберите **Ubuntu 24.04** → подтвердите.

Важно:

- переустановка **удаляет все данные** на сервере — делайте это до того, как
  что-то настроите;
- после переустановки рег.ру ещё **10–15 минут** сам доустанавливает софт,
  в это время сервер лучше не трогать;
- письмо о завершении придёт на почту аккаунта.

## Шаг 3. Возьмите IP и пароль root

Оба значения приходят в письме после создания сервера, а также показаны
в личном кабинете: ваша услуга VPS → вкладка **«Доступы»** → блок
**«Доступ к серверу»**.

Если пароль потерян: вкладка **«Операции»** → **«Сбросить пароль пользователя
root»**, новый придёт письмом.

Запишите:

```
IP:     123.123.123.123
root:   пароль из письма
```

## Шаг 4. Пропишите домен на сервер

Личный кабинет → раздел **«Управление DNS»** (или «Домены» → нужный домен →
«DNS-серверы и зона») → кликните по **info-field.ru** → **«DNS-записи»**.

Проверьте, что для домена стоят **DNS-серверы рег.ру**
(`ns1.reg.ru`, `ns2.reg.ru`) — иначе записи в этой панели ни на что не влияют.

Нужны две записи типа **A**:

| Тип | Имя | Значение |
|---|---|---|
| A | `info-field.ru.` | IP вашего VPS |
| A | `www.info-field.ru.` | IP вашего VPS |

Нажмите **«Создать запись»**, выберите тип **A**, в поле «Имя» впишите домен
**с точкой на конце**, в поле IP — адрес сервера.

Если A-записи уже есть и указывают на старый хостинг — **измените** их, а не
добавляйте вторые: два разных IP на одном имени приведут к тому, что сайт будет
открываться через раз.

Обновление занимает от 15 минут до часа (до 24 часов, если вы только что
меняли DNS-серверы). Проверить с локального компьютера:

```bash
nslookup info-field.ru
```

Должен вернуться IP вашего VPS. Пока не вернулся — сертификат HTTPS выпустить
не получится.

## Шаг 5. Подключитесь к серверу

Файлы **не** загружаются по FTP, как для PHP-сайта: проект нужно не положить
на диск, а установить и запустить. Делается это по SSH.

**Windows:** скачайте [PuTTY](https://www.putty.org/) или используйте
встроенный терминал (Win+R → `cmd`):

```
ssh root@123.123.123.123
```

**macOS / Linux:** терминал, та же команда.

При первом подключении согласитесь с отпечатком ключа (`yes`), затем введите
root-пароль из шага 3 — **он не отображается при вводе, это нормально**.

> В панели рег.ру есть и «Консоль» (VNC) прямо в браузере — на случай, если
> SSH не открывается. Но в ней нельзя вставлять текст, поэтому для установки
> удобнее обычный SSH.

## Шаг 6. Установка одной командой

Дальше всё уже описано в [`DEPLOY.md`](DEPLOY.md), но вот короткий путь.
Команды выполняются на сервере, по очереди:

```bash
# 1. Git и код проекта
apt update && apt install -y git
git clone https://github.com/Artur717661/infofield.git /root/infofield
cd /root/infofield
git checkout claude/analytics-dashboard-frontend-nvvjje

# 2. Автоматическая настройка: пакеты, база, Python, firewall, fail2ban
bash deploy/setup-server.sh
```

Скрипт работает 5–10 минут. Если репозиторий приватный, git спросит логин и
**токен** (не пароль от GitHub): GitHub → Settings → Developer settings →
Personal access tokens → Fine-grained → доступ только к этому репозиторию,
права Contents: Read.

```bash
# 3. Ключ Gemini (пароль базы скрипт подставил сам)
nano /opt/infofield/backend/.env
```

Впишите свой `GEMINI_API_KEY`, сохраните: `Ctrl+O`, `Enter`, `Ctrl+X`.

```bash
# 4. nginx и сертификат HTTPS (домен уже должен указывать на сервер!)
cp /opt/infofield/deploy/nginx/info-field.ru.conf /etc/nginx/sites-available/info-field.ru
ln -sf /etc/nginx/sites-available/info-field.ru /etc/nginx/sites-enabled/
rm -f /etc/nginx/sites-enabled/default
certbot --nginx -d info-field.ru -d www.info-field.ru
nginx -t && systemctl reload nginx

# 5. Сборка фронтенда
curl -fsSL https://deb.nodesource.com/setup_22.x | bash -
apt install -y nodejs
cd /opt/infofield/frontend
sudo -u infofield npm ci
sudo -u infofield npm run build

# 6. Запуск
systemctl start infofield-backend infofield-gateway infofield-refresh.timer

# 7. Администратор — придумайте пароль от 12 символов
cd /opt/infofield
sudo -u infofield venv/bin/python -m gateway.cli create-admin admin

# 8. Данные за сентябрь 2025 — июль 2026
systemctl stop infofield-backend
sudo -u infofield venv/bin/python tools/seed_demo_data.py
systemctl start infofield-backend
```

Откройте **https://info-field.ru** — должен появиться экран входа.

## Если файлы нужно загрузить без git

Так делать не обязательно (git проще), но если хочется — можно закинуть архив
через SFTP, а установку всё равно запускать по SSH.

**Windows:** [WinSCP](https://winscp.net/) или FileZilla, протокол **SFTP**
(не FTP), порт 22, логин `root`, пароль из шага 3.

1. Скачайте архив проекта с GitHub: кнопка **Code** → **Download ZIP**.
2. Загрузите zip в `/root/` на сервере.
3. По SSH распакуйте и запустите установку:

```bash
apt update && apt install -y unzip
cd /root && unzip infofield-*.zip && mv infofield-* infofield
cd infofield && bash deploy/setup-server.sh
```

## Проверка, что всё поднялось

На сервере:

```bash
systemctl status infofield-backend  --no-pager
systemctl status infofield-gateway  --no-pager
systemctl status nginx              --no-pager
```

Все три — `active (running)`.

С любого компьютера:

```bash
# данные без входа должны отдавать 401
curl -s -o /dev/null -w "%{http_code}\n" https://info-field.ru/api/telegram

# http должен перебрасывать на https (301)
curl -s -o /dev/null -w "%{http_code}\n" http://info-field.ru
```

Оценка настроек снаружи: https://securityheaders.com/?q=info-field.ru
(ожидаемо A или A+).

## Частые проблемы именно на рег.ру

**Сайт не открывается, хотя всё запущено.** У рег.ру есть свой firewall на
уровне услуги, отдельно от `ufw` внутри сервера. Личный кабинет → ваша услуга
VPS → раздел с сетью/firewall: убедитесь, что 80 и 443 разрешены.

**`certbot` не может выпустить сертификат.** Домен ещё не указывает на сервер.
Проверьте `nslookup info-field.ru` и что в панели рег.ру для домена прописаны
DNS-серверы рег.ру, а не старого хостинга.

**Порт 80 занят, nginx не стартует.** На сервере уже висит ISPmanager или
Apache из шаблона рег.ру:

```bash
ss -tlnp | grep -E ':80|:443'      # посмотреть, кто занял
systemctl disable --now apache2    # если это Apache
```

Либо переустановите ОС «без панели» (шаг 2).

**Сервер отвечает медленно, процессы падают.** Не хватает памяти — типично для
тарифа с 1–2 ГБ. Проверьте `free -m` и `dmesg | grep -i "out of memory"`.
Лечится повышением тарифа в личном кабинете (**«Сменить тарифный план»**) или
добавлением swap:

```bash
fallocate -l 2G /swapfile && chmod 600 /swapfile
mkswap /swapfile && swapon /swapfile
echo '/swapfile none swap sw 0 0' >> /etc/fstab
```

**Забыли пароль root.** Личный кабинет → услуга VPS → **«Операции»** →
**«Сбросить пароль пользователя root»**.

**Забыли пароль администратора дашборда.** Это не пароль сервера, сбрасывается
на сервере:

```bash
cd /opt/infofield && sudo -u infofield venv/bin/python -m gateway.cli reset-password admin
```
